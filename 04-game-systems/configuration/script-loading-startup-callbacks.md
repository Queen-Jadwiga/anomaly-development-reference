## VM initialization and native startup boundaries

AI-space initialization constructs a script engine and calls its init. The selected simulator constructor also calls `restart_all`; unless `-keep_lua` is present, that path tears down selected UI/object-factory state and initializes the script engine again. Engine init calls storage reinit, which closes the old Lua VM and creates a new one. It then opens Luabind, installs callbacks, exports classes and global autoload, clears unlocalizer state, requests `_G.script` with reload enabled, registers configured classes/object factory, and loads common scripts in the game build. Debugger/build branches retain separate conditions. This is not a general claim that every quickload recreates every native cache or that external handles survive VM reconstruction. N01–N05, `ai_space.cpp:66–70`, `alife_simulator.cpp:26–78`, `script_engine.cpp:371–430`, `script_storage.cpp:391–472`.

The simulator resolves `pSettings[alife].start_game_callback`, asserts a matching functor and invokes it **before** the selected `load(...)` call. The actual configured name and body are absent from the selected engine gamedata. A function named startup is therefore not proof of restored native groups, actor/binder/UI readiness or the effective route into `axr_main.on_game_start`. Existing [A-Life callback phases](../alife/callback-phase-reference.md) remain canonical for those native phases. N02.

`script.ltx` separately supplies `[common] class_registrators` and `[common] script`. Registrators resolve typed functors and receive the object factory; unresolved ones log/continue. The common script list requests each module, then tests a **global** `<module>_initialize` function and invokes it if present. Neither list is universal discovery of every startup handler. The selected debug-disable guard can bypass these routines, and the actual script.ltx is missing from this gamedata scope. N07, `script_engine.cpp:446–481,529–561`; [CONFIG-02 settings rules](ltx-ini-dltx.md).

## Ordinary module loading and lookup

Global `_G.__index` autoload requests a missing key through `process_file_if_exists(key,false)` and then raw-fetches that key. Ordinary loading constructs `$game_scripts$/<module>.script`; it does not fall back to `<module>.lua`. It skips a previously existing namespace table unless reload is requested. Quiet misses remember **one last name plus length**, not every absent module, and can short-circuit another quiet request. `unload()` restores the recorded Lua stack level and clears that miss entry; its body does not destroy namespaces/VM. A warning-enabled explicit request bypasses the quiet-miss shortcut. Lua `prefetch(module)` uses the ordinary process_file route and returns no success receipt. N06/N08/N09/N18, `script_engine.cpp:172–177,340–365,483–527,614–626`, `script_engine_script.cpp:122–125,232–239`.

`namespace_loaded` traverses `_G` with raw table lookups and checks table existence; missing returns false, a non-table namespace collision takes a fatal path. It is **not an execution-completion flag**. A named module header creates/assigns its namespace table, sets the chunk environment and, in the ordinary header, delegates missing names to `_G`. The `-_g` alternate header exposes explicit `this._G` without that metatable fallback. `_G` chunks bypass the namespace header. Nested low-level namespace construction uses generated assignment structure, not a certified preserve-all-sibling merge. N03/N12/N15, `script_storage.cpp:43–65,681–787,1054–1123`.

For configured native functors, the parser splits on the **last dot**. An unqualified name uses `_G`; a qualified name first requests the module before its namespace's first dot, then checks the remaining namespace path and exact member type. The storage typed-object check enumerates actual members rather than treating inherited fallback as a declared function. Luabind object traversal and functor conversion follow only after that check. Matching a function does not establish its return semantics, callback registration or readiness; `_G` and another namespace spelling must not be silently equated. N10/N11/N16, `script_engine_inline.h:26–57`, `script_engine.cpp:563–590`, `script_storage.cpp:1125–1177`.

## Compilation, execution, failure and reload

Before ordinary do_file compilation, the native loader scans root `unlocalizers/*.ltx` once per its initialization state, merges section-key names into sets and can rewrite selected top-level local lines for the matching lowercased namespace. Source rewriting precedes the namespace header and compilation. The selected regex handling can expose all variables on a matching multi-variable declaration; it is not a general Lua AST transformation. Effective directives, consumer patching and fuller rewrite limits remain CONFIG-04 work. N13/N14, `script_storage.cpp:800–1052`.

The loader returns false locally on open/compile failure and on a main-chunk `lua_pcall` error, restoring the stack in the relevant wrappers; process_file itself is void and ignores that returned load status. This local protected call does not roll back earlier Lua assignments, registrations or external/native effects. A runtime failure after the header created its table can leave a namespace that subsequently satisfies namespace_loaded, suppressing an ordinary retry. Compile failure and runtime partial execution are distinct. No blanket recoverability claim across outer engine/assertion handlers is made. N08/N12–N15.

Forced native module reload executes new top-level code and assigns new namespace state; it does not revoke old closures, captured originals, listener identities or borrowed pointers held elsewhere. The Lua prefetch export has one module argument and does not expose the native boolean reload overload. VM reinit, module reload, stack unload, callback unset and game restoration are separate operations. N03–N05/N08/N09/N18; [INI lifetime](ltx-ini-dltx.md).

## Module discovery versus startup handler execution

`axr_main` performs settings/check_on_launch work at module evaluation before its local callback registry is declared. Its active `on_game_start` enumerates nonempty **root `*.script`** files, applies its literal ignore list, and reads `_G[module]` and that module's on_game_start. Those lookups can autoload/evaluate module top-level code while the first pass is still gathering names. A second pass calls the collected startup handlers directly. It has no local protected-call wrapper, completed-once flag or readiness gate. Reinvocation can repeat handlers even if module evaluation was skipped; an error can leave prior discovery/handler effects in place. A module loaded only as another module's dependency need not have its startup handler called by that access alone. S08/S13, `axr_main.script:14–42,627–664`.

The extended native file-list wrapper rescans, enumerates an ordered FS_FileSet and copies its entries into a vector; the selected set compares names. That establishes source enumeration order, while module dependency autoload can still change evaluation order. A lexical filename cannot by itself dictate the final replacement or callback execution order. UI DXML discovery is another evaluation-time pass: it gathers root modxml modules, sorts the gathered names, invokes their registration handlers, then processes a forced-load list. It is not the axr_main startup pass or per-XML dispatch. N19–N21/S12, `fs_registrator_script.cpp:131–167,287`; [UI registration rules](../../03-ui-pda/xml-dxml-callback-errors-ui04b-oct11.md).

## Shared registry, identity, registration and removal

The active `axr_main` local intercepts map defines event names including on_game_load/save_state/load_state. Old comments about deleting unused callbacks during on_game_load have no active implementation in this inspected module; do not turn the comments into a mandatory registration deadline. Missing installed wrappers or other modules can still impose their own policy. New named tables can be added by callback_add; adding an existing name logs/callstack without replacing it. S01/S05, `axr_main.script:46–53,205–222,497–579`.

Registration uses the **exact Lua function/userdata identity** as a key. It rejects a false/nil listener or absent event by log/callstack and return; it does not implement comprehensive listener-type or callable-method validation for every truthy value. Dependency lists accept nil/false, a function/userdata, or a table of such values, copied privately. Invalid dependencies/tier assert; missing dependency targets remain forward references. Re-registering an existing identity replaces its constraints/tier while preserving fallback registration position. A new closure with the same textual function body is another identity. Registration returns no boolean success receipt. S02–S05.

The October reorder implementation validates hard PRE → NORMAL → POST tiers, same-tier dependencies, self/cycle errors and contradictory cross-tier constraints. Stable topological selection uses earlier registration order among currently eligible listeners. It writes numeric ranks only after the full proposed graph succeeds; failed reorder causes callback_set to restore its recorded registration fields. This is ordering-state rollback, not reversal of arbitrary startup/gameplay effects. Compatible cross-tier relations are already implied by tiers. S04/S05, `axr_main.script:319–579`; the independently pinned September implementation retains [its different index-only model](../alife/callback-phase-reference.md#build-boundary--september-versus-october-dispatcher).

Unsetting removes that identity, order and own rule, then reorders. Other rules retain function target references for possible future re-registration, while userdata targets are scrubbed from other before/after lists. This retention can keep referenced function closures alive; unregistering a listener does not automatically discard every external reference. Unset reports reorder failure without a symmetric registration-style rollback. Correct listener removal still requires the same identity and event name; callback priority is not a native object lifetime grant. S03/S06, `axr_main.script:273–309,581–607`.

## Dispatch, mutation and reentry

`make_callback(name,...)` directly calls functions with the arguments, or an object's named method with self prepended. Return values are discarded; there is no per-listener pcall, listener-result reduction or local reentry guard. Mutable table arguments are shared references; later listeners can see earlier writes, and a throwing listener can prevent later invocation without undoing prior changes. Native veto/return consumers, such as selected item flags, require their own emitter contracts. S07 and existing [world use consumers](../world/supplied-consumers.md).

The supplied `_g_patches.spairs` routes this value comparator to `hspairs`: it collects **keys at iterator creation**, reads live table values, and maintains a heap using live priorities. Removed nil entries are skipped; newly added keys are not in that initial outer iterator. Reordering/re-registering keys during dispatch does not rebuild the entire remaining heap, so a frozen listener-value/order snapshot is not established. A nested make_callback builds a separate iterator from current state and can repeat listeners; no once-only or reentrant transaction follows. This extends, rather than contradicts, ALIFE-10's statement that make_callback has no local listener snapshot. S07/S10, `axr_main.script:609–624`, `_g_patches.script:413–415,769–793,814–887,1074–1081`. Actual installed spairs/wrapper winners remain unknown.

## Global bridges and debug-only dispatcher

The available `_g_patches` assigns global RegisterScriptCallback to axr_main.callback_set and defines PRE/NORMAL/POST constants plus fixed-tier Pre/Post wrappers. These wrappers discard the callee return. Their top-level assignments do not establish the missing effective `_G.script` caller, final global SendScriptCallback/UnregisterScriptCallback routes, or which replacement wins later. Native class/functor hooks, shared dispatcher calls and object-bound callbacks remain separate mechanisms. S09; [API](../../02-lua-api/configuration/script-callback-api.md), [existing lifecycle phases](../alife/callback-phase-reference.md).

**Correction and newly traced route:** the standalone dynamic_callbacks.lua declares **five** events: save, load, update, save_state and load_state. Its function registration is a true-valued key set; sending uses pairs, ignores returns and has no tiers/dependencies. Unlike ordinary .script autoload, storage reinit explicitly loads it through LoadKernelScriptToGlobal when `lua_debug` is enabled. That helper compiles/executes the file in the global environment without a named-module header. Thus this selected debug path can install its global Register/Unregister/Send functions **before** later engine `_G` loading and module assignments, which can replace them again. It does not prove the final effective global route or generic marker/use events. N04/N17/N22/S11.

Earlier WORLD-04 C12 and CONFIG-01 K08 wording counted six names; those immutable ledgers remain preserved with this explicit amendment. Their installed-alias uncertainty remains valid, but the selected debug-only global installation path is now established. The earlier assertion that file presence alone does not prove installation is not a claim that no such native route exists. Do not combine the small pairs-based dispatcher with axr_main's registry/order as one implemented contract.
