## Definitions, lookup and side-effecting defaults

BETA150 main ui_options constructs preset/localization readers during module evaluation, declares options plus module-local pending/backup/index/type tables, and builds options through init_opt_base/init_opt_coder. The coder assumes its selected tree layout, creates faction/radio entries and records allowed control types under slash-delimited paths at supported depths. The selected coder does not explicitly clear opt_index/opt_val before rebuilding; definition changes need their own index reconciliation. Presence of a row or bounds is not a universal schema validator. E08's unlocalizer directive can expose opt_temp later, while the other local tables remain separate owners in this selected file. B01/B02, `ui_options.script:36–89,688–776`.

Direct `ui_options.get(id)` initializes the tree if empty, then reads `[options] id` through axr_main.config with the indexed type. A non-nil stored value wins before definition/current/console checks. Otherwise a command option reads the console, with selected numeric clamp/round behavior; a function-valued default executes external exec, and literal/function defaults are written and saved by this getter. It does **not** use the UI method's v.curr branch. Unknown definition lookup can return `{}`; an existing stored value can still be returned, while no stored/declared default can lead to a nil write attempt. No universal path/type/default validation follows. `set(id,value)` writes and saves directly, without local schema bounds, UI pending-cache reconciliation, functor/console execution or option-change emission. B03, `ui_options.script:1091–1170`.

The supplied menu's `GetCurrentValue` instead uses pending non-nil value → v.curr functor → v.cmd console branch → persisted config branch. `GetDefaultValue` evaluates its default and can write a previously missing persisted value, marking Save_AXR, even while merely preparing a control. `GetValue` considers explicit default/preset flags first, then current/default fallback and selected track clamps. Nil is the missing sentinel; false is a legitimate value. A displayed bounded value is not proof that every stored/direct-set/preset value was validated or that every consumer cache refreshed. B05–B07, `ui_options.script:2096–2191`.

## Pending edits, presets and accept/cancel

`CacheValue` backs up an initial GetValue, records a non-nil value differing from that backup in opt_temp, otherwise removes the pending entry, updates UI color and pending count. It does not persist or call option consumers. Track/display reads may clamp values, but CacheValue itself is not a general bounds/content validator. External writes can leave an already captured backup/pending value stale. B08, `ui_options.script:2236–2266`.

Preset selection maps translated display text back to a declared preset name, checks the section, iterates rows and requires a matching option definition with type. It respects visibility precondition and stages through CacheValue. Type 1 conversion is **exact value == "true"**; it is not native lowercased on/yes/true/1 parsing or the bundled helper's four-token test. Type 2 uses tonumber; no general list-content membership or track-bound check is applied in this callback before staging. Later control rendering/reset and accept are separate operations. The existing [world underground-key discrepancy](../world/supplied-consumers.md) remains literal and qualified; no alias is invented. B04, `ui_options.script:1930–1997`.

| Accept stage | Selected effect | Limit |
| --- | --- | --- |
| Iterate pairs(opt_temp) | Resolve definition; write config unless v.curr; mark Change_Done | No guaranteed order across independent option keys or transaction around the loop |
| Per-row application | Invoke functor, possibly gated by postcondition; mark restart flags; execute cmd with bool formatting | External exec/command bodies decide completion/error; a skipped functor need not undo an earlier config write |
| Shared save | Save axr config when requested; save keybinds; cfg_save for console state | Config, user.ltx/keybind and consumer state are different owners; no atomic whole-profile commit |
| Change event | Send on_option_change only when level.present() and Change_Done | Main-menu accept/direct set do not establish this emitter path; listener refresh requires effective shared routing |
| Finalization | Clear pending and backup, then On_Cancel | Event occurs before clear; failure protection/rollback is not implemented locally around all stages |

B09, `ui_options.script:2353–2440`; [shared dispatcher limits](script-loading-startup-callbacks.md). Pending data can be inspected by effective functors/listeners, but the event has no old/new table arguments in this emitter. On_Cancel hides/exits, applies requested video restart, reports restart/change and resets selected flags; it does not itself clear every pending/backup entry. On_Discard explicitly clears opt_temp and resets controls before cancel; opt_backup has no explicit clearing in that body. Do not equate every cancel call with complete state rollback. B10, `2441–2477`.

## Warfare refresh and replacement phase

`warfare_options.update_settings` replaces its factions table and reads many UI paths into general/faction fields and aliases. Existing holders of the old faction table are not automatically retargeted. The module's on_game_start registers the option-change listener; the separate warfare.on_game_start calls update_settings for initial values, then sets WARFARE and registers strategic/storage listeners. Getting/setting a single menu value is not a synchronous refresh of every Warfare consumer. Keep existing [WAR-003 controls](../warfare/policy-controls.md) authoritative for actual policy/clock effects. B11/B12.

The `sim_squad_scripted...check_online_status` definition is a module-level method replacement that writes forced_online_status. By contrast `override_functions` only defines an installer for heli and squad helpers; the bounded .script search in the supplied BETA150/ZIP142 packages finds its definition, without a direct invocation. An external/dynamic caller can still exist. Do not label every named replacement active merely because it is defined. B13, `warfare_options.script:224–229,255–299`; existing [ALIFE-08](../../08-research/investigations/2026-10-11-ALIFE-08-switching-eligibility.md).

## Engine option extension and builder assumptions

ENGINE1011 ui_options_modded_exes.on_xml_read is an **installation handler**, invoked by the separately traced DXML discovery pass, not a listener that applies a menu change for every XML text load. It assigns namespace variable ui_options_base from the current init_opt_base, replaces that function, then invokes it. The wrapper calls the saved slot, appends the Modded Exes GROUP, adapts selected sound metadata, inserts monitor/weather declarations conditionally and reruns the coder if needed. Conditional guards around selected rows do not make the whole installer repeat-safe: GROUP is appended unconditionally after the base call. The root GROUP uses options_builder.import_into(this) and composed option modules. E01/E04; CONFIG-03 S12 remains the canonical discovery trace.

**Conditional repeat-install hazard:** calling this installation handler twice in the same module instance can set the shared ui_options_base slot to its own earlier wrapper. That earlier closure reads the same mutable slot and can call itself recursively. A fresh module environment, a different intervening replacement or an actual once-only caller can alter that case. This source deduction is not a reproduced installed crash, and no third-party code is modified. E01, `ui_options_modded_exes.script:1–123`.

Selected builders mutate and return the supplied argument tables rather than creating an immutable schema. Check sets type/val/default/command; track delegates console bounds, swaps an explicitly reversed range, and removes a non-string command. It does not prove current or persisted numeric values are finite/in bounds. Page removes a header from the list, assigns children and prepends a slide; literal `head.sh = head.sh or true` does not preserve an explicit false. import_into requires an existing metatable, replaces __index with a builder-first lookup and then invokes/indexes the prior fallback when appropriate. Existing metatable/environment and later import order matter; all builder/widget kinds are outside this selected pass. E02/E03, `options_builder.script:41–83,329–348,365–380`.

## Unlocalizers, script cache helpers and native cache

ENGINE1011's `[ui_options] opt_temp` directive requests exposure of that local variable; `[_G] ini_cache` separately names a core global cache. Native do_file discovers directives once, lowercases section/namespace matching and merges requested key names. It transforms selected regex-matched local declarations before namespace-header compilation. A selected matching multi-variable declaration can expose more than one variable; a declaration without initialization can gain `= nil`. This is source preprocessing, not a runtime callback subscription or a general AST rewrite. Exact directive availability, line form and winning source decide exposure; the original base _G definition is not supplied. E08/E09/N01; [CONFIG-03 loader](script-loading-startup-callbacks.md).

The available _g_patches disables USE_INI_MEMOIZE/clears script cache tables and patches the **existing** ini_file_ex class methods, including one-time per-instance cache clearing before r_value. It later aliases ini_file_ex to a newly declared native-derived class already traced by CONFIG-02. Old instances do not simply become instances of that new class alias; which object was constructed before/after which assignment matters. Both selected write paths delegate to native w_string. The separate SYS_GetParam type dispatch's bool branch calls ini_sys:r_bool_ex without forwarding the declared default, unlike its string/float branches. This is a literal helper difference, not a universal default API. E05–E07, `_g_patches.script:452–574`; CONFIG-02 S02.

These script-cache edits do **not** invalidate CInifile's native filename cache, reload ini_sys, rerun module startup or rewrite every consumer's copied values. UI methods that attempt to create a missing persisted row and the selected native-derived helper's existing-key writer check cannot be combined into a certified successful installed path without the actual class/instance/construction/writer chain. ENGINE1011 and BETA150 are alternative source baselines, not proof that this combination executes. [Native cache/writer contracts](ltx-ini-dltx.md).

## Captured originals and startup wrappers

The selected trade patch captures trade_manager.trade_init **during module evaluation** and calls that local original from its replacement, with actor/profile gates and resupply timestamp restoration. The selected binder fix captures current stalker/monster net_destroy **when its installer is called at startup**, calls originals before bookmark cleanup and can wrap an already wrapped function on reinstallation. Neither capture retroactively follows later assignments by other modules. Preserve [economy](../economy/trader-configuration.md) and [world bookmark semantics](../world/supplied-consumers.md) rather than retracing their consumers. E11/E12.

dynamic_items_by_level.on_game_start reassigns a shared local base_init_settings slot and installs its wrapper. The wrapper calls that slot **before** checking its resolved guard, sets resolved before resolving and does not forward the original result. Repeating installation in the same module while game_setup.init_settings is already that wrapper can set base_init_settings to itself; the guard does not prevent that recursive call. Once-only resolution, repeat-safe installation and final winning function are distinct contracts. Missing producer/upvalue/config data can also be consumed without retry in the selected guard order; [WORLD-04](../world/supplied-consumers.md) retains that earlier finding. E10, `dynamic_items_by_level.script:9–10,71–83`.

## Package comparisons and effective inputs

Seven comparisons reproduce with five equal results. BETA150 main ui_options, warfare_options and preset includes are byte-identical to ZIP142 counterparts in this scope. The two BETA150 optional ui_options files differ from main: selected GAMMA declarations change anisotropy control/population defaults and comment out the default button; the Dynamic Mutants-related variant adds option declarations. Their **normalized GetValue-through-before-OnKeyboard method slice** is equal to main. That slice equality does not make the whole menus, dependencies or installed file winners equivalent. P01/P02 and comparison ledger; no variant is merged or selected as active.

BETA150 main preset includes declares 13 files, with only four present in that main presets folder; the remaining names require base/other effective resources. CONFIG-02's permitted-include open/assert contract still applies if a target is actually unavailable at load. A partial uploaded addon folder is not evidence of a broken installed include chain. The scope record covers ENGINE1011 gamedata (161 files), full BETA150 including optional patches (62), and ZIP142 gamedata (29); requested names/hash matches are qualified to those roots. B14.

Obtain winning _G/global/class/exec helpers, axr_options/localization/preset resources, option definitions and current inputs, native build/debug/cache settings, directive files, startup callers and later patches. Trace the actual persistence writer and Send/Unregister routes, consumer copies and error behavior before claiming a setting applied everywhere. No MCM implementation is certified by these menu definitions. CONFIG-04 finishes the selected consumer pass and [consolidation/bounded audit](development-reference.md); effective installed integration remains partial and runtime deferred.
