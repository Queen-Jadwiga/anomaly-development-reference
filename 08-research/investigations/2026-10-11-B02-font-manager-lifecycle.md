# B-02 — client UI font manager lifecycle and device-reset handling

> ADR document set: **v0.1.48**. Research revisions and source/build versions below describe their original scope.

**Baseline:** user-supplied X-Ray Monolith source `2026.10.11`. **Status:** source research complete; runtime checks deferred. **Scope:** construction, destruction, device reset; not all engine font subsystems or precise cause of CtZ's prior crash.

## Source-verified call sequence

1. `CGamePersistent::OnAppStart()` loads materials, calls `init_game_globals()`, invokes its parent `OnAppStart()`, then allocates `m_pUI_core = xr_new<ui_core>()` and subsequently creates the main menu. Evidence: [`GamePersistent.cpp:156–165`](https://github.com/themrdemonized/xray-monolith/blob/2026.10.11/src/xrGame/GamePersistent.cpp#L156-L165).
2. Client-side `ui_core::ui_core()` creates the cursor and `m_pFontManager = xr_new<CFontManager>()`; the dedicated-server branch sets these pointers to NULL. Then it calls `ui_core::OnDeviceReset()` (this sets UI scale/frustum, *not* font resources). Evidence: [`ui_base.cpp:112–121`](https://github.com/themrdemonized/xray-monolith/blob/2026.10.11/src/xrGame/ui_base.cpp#L112-L121) and [`ui_base.cpp:213–232`](https://github.com/themrdemonized/xray-monolith/blob/2026.10.11/src/xrGame/ui_base.cpp#L213-L232).
3. `CFontManager::CFontManager()` registers `this` with `Device.seqDeviceReset` at `REG_PRIORITY_HIGH`, collects addresses of named font pointers, zeros them, and invokes `InitializeFonts()`. Evidence: [`HUDManager.cpp:31–53`](https://github.com/themrdemonized/xray-monolith/blob/2026.10.11/src/xrGame/HUDManager.cpp#L31-L53).
4. `InitializeFonts()` enumerates named font sections. `InitializeFont()` reads a texture name and shader from settings; if the font pointer is null it creates `CGameFont`, otherwise it calls `F->Initialize(...)` on the existing instance. A missing font texture name is guarded by `R_ASSERT(font_tex_name)`. Evidence: [`HUDManager.cpp:55–85`](https://github.com/themrdemonized/xray-monolith/blob/2026.10.11/src/xrGame/HUDManager.cpp#L55-L85).
5. Native device-reset processing invokes registered reset listeners: `seqDeviceReset.Process(rp_DeviceReset)` is present in both shown renderer-reset paths. `CFontManager::OnDeviceReset()` calls `InitializeFonts()`; reinitialization need not change the `CGameFont*` address. Evidence: [`Device_destroy.cpp:78–102`](https://github.com/themrdemonized/xray-monolith/blob/2026.10.11/src/xrEngine/Device_destroy.cpp#L78-L102), [`Device_destroy.cpp:176–187`](https://github.com/themrdemonized/xray-monolith/blob/2026.10.11/src/xrEngine/Device_destroy.cpp#L176-L187), and [`HUDManager.cpp:105–108`](https://github.com/themrdemonized/xray-monolith/blob/2026.10.11/src/xrGame/HUDManager.cpp#L105-L108). `ui_core` separately subscribes at `REG_PRIORITY_NORMAL` by inheriting `CDeviceResetNotifier`: [`ui_base.h:9–18`](https://github.com/themrdemonized/xray-monolith/blob/2026.10.11/src/xrGame/ui_base.h#L9-L18).
6. `CGamePersistent::OnAppEnd()` deactivates/deletes the main menu, then deletes `m_pUI_core`, before deleting its wallmark manager and calling the parent `OnAppEnd()`. `ui_core::~ui_core()` deletes its font manager; `CFontManager::~CFontManager()` unregisters from `seqDeviceReset` and deletes all named fonts. Evidence: [`GamePersistent.cpp:168–182`](https://github.com/themrdemonized/xray-monolith/blob/2026.10.11/src/xrGame/GamePersistent.cpp#L168-L182), [`ui_base.cpp:234–238`](https://github.com/themrdemonized/xray-monolith/blob/2026.10.11/src/xrGame/ui_base.cpp#L234-L238), [`HUDManager.cpp:88–95`](https://github.com/themrdemonized/xray-monolith/blob/2026.10.11/src/xrGame/HUDManager.cpp#L88-L95).

## Narrow conclusions and implementation cautions

- The client lifecycle is **app start → UI core → font manager → named fonts**, and **app end → UI core deletion → font manager destruction → font deletion**. This traces the relevant ownership cascade rather than every subsystem's global shutdown order.
- **Device reset reinitializes** manager fonts; it does *not* ordinarily delete and recreate the manager or every font pointer. Do not infer that shader/texture internals remain unchanged or that external cached resources are safe across resets.
- Font section/texture/shader configuration is needed during initialization. Source alone cannot prove which precise missing asset, registration, or early access caused a historical CtZ crash.
- `ui_core` has no client fonts in the dedicated-server branch; accessing `UI().Font()` in that branch is not established as safe.
- This establishes native implementation, not the exact runtime results under GAMMA or any Lua userdata lifetime guarantees. Those tests are deferred.

**B-02 outcome:** source research complete. Further work on arbitrary Lua-side `CGameFont` pointer lifetimes, custom font configuration failures, or runtime reset robustness belongs in separate narrowly scoped questions; no blanket guarantee is made here.
